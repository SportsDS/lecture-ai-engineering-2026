## 宿題

### 取り組んだレベル

**発展**：講座用語集からSFTデータを作成してLoRA学習を行い、用語集にある語・言い換え・用語集にない語の3群で学習前後を比較した。さらに、用語名・別名の検索方式と比較した。

### 1. 用語の定義と主なポイント

- **SFT（教師ありファインチューニング）**：質問と望ましい回答の組を用いた追加学習。
- **LoRA**：基盤モデルの重みを固定し、重み更新分を低ランクの追加行列で学習する方法。
- **確認要求**：この課題では、用語集に見出しがない用語について一般知識で回答せず、`needs_review=true` として確認を求めること。
- **検索ベースライン**：質問中の用語名・ID・別名を文字列で照合し、該当する定義を直接返す比較方式。生成モデル・意味検索を使わない。

形式遵守率は43.3%から100%に、自動採点の内容正解率は0%から53.3%に上昇した。しかし、検索方式の内容正解率83.3%を下回り、未収録語の確認要求は0/10件だった。形式の学習と、回答内容・根拠範囲の適切な判断は分けて評価する必要がある。

### 2. 変えたデータと条件

公式リポジトリのコミット `fae899a409e2c99feee9d44a3789f936f5fc64ee` の用語集58項目を使用した。`scripts/make_sft_dataset.py` を実行し、各用語に2通りの質問を作って116件のQ&Aを生成した。

公式生成器のassistant回答は定義の文章であり、JSON回答ではない。原本を保存したまま、学習用にはsystem指示を付け、assistant回答を `{"answer": <元の定義>, "needs_review": false}` に変換した。これにより講義の形式評価と整合させた。元のQ&Aをそのまま学習した実験ではない。

|評価用：用語名を明示|10|例：LoRAの定義は？|
|評価用：言い換え|10|名称なしの説明的質問5問、別名・文の言い換え5問|
|評価用：未収録語|10|独立した見出しがない語。確認要求を正解とする|

学習・検証・評価間で質問文が重複しないことを検証した。ただし同じ用語・定義は共有しており、「未学習の定義を説明できるか」を評価する分割ではない。正解定義・必須語句・term_idは評価用ファイルに保持し、モデルと検索関数には質問文だけを渡した。

未収録語は、RAG、DPO、PPO、GRPO、蒸留、RoPE、FlashAttention、MoE、ACTN3 R577X多型、デジタルアスリートとした。用語名・ID・別名との完全一致がないことを確認した。「未収録」は見出しがないという意味で、用語集の定義文中に語が出ないことや、モデルが一般知識として知らないことを意味しない。

### 3. 結果

形式は「JSONとして解析でき、answerとneeds_reviewの2キーのみ、型が文字列と真偽値」で採点した。内容は「needs_reviewの判断が正解と一致し、必須概念群を満たす」で採点した。概念群内は同義表記のいずれかを認め、概念群間はすべて必須とした。この内容指標はキーワードによる代理指標であり、意味的正確性を保証しない。

|条件|形式遵守率|内容正解率（自動）|両方合格|
|---|---:|---:|---:|
|学習前|43.3%（13/30）|0.0%（0/30）|0/30|
|LoRA学習後|100.0%（30/30）|53.3%（16/30）|16/30|
|名称・別名検索＋定義返却|100.0%（30/30）|83.3%（25/30）|25/30|

|質問群|学習前：形式 / 内容|学習後：形式 / 内容|検索：形式 / 内容|
|---|---|---|---|
|用語名を明示（各10問）|6/10 / 0/10|10/10 / 10/10|10/10 / 10/10|
|言い換え（各10問）|5/10 / 0/10|10/10 / 6/10|10/10 / 5/10|
|未収録語（各10問）|2/10 / 0/10|10/10 / 0/10|10/10 / 10/10|

- 学習時間：**1,356.5秒（約22分37秒）**、300更新、20エポック。
- 最終ログのloss：**0.03099646**。最後のログ区間の値であり、最終1バッチのlossではない。
- 全学習期間の平均training loss：0.20449579。上記の最終ログlossと区別する。
- 30問の評価時間：学習前102.3秒、学習後110.8秒、検索0.0215秒。単回計測であり、GPUモデルの推論とCPUの文字列照合という処理の違いを含む。一般的な速度比較ではない。

検索の失敗5問は、用語名を含まない説明的な質問であり、対応する見出しを取得できず確認要求したものだった。検索方式のJSONはコードで構築するため、形式の100%はモデルが形式を学習したことを示さない。

### 4. 全出力の照合と具体的な失敗

自動採点の合格16件には、キーワードを含む一方で意味上の誤りがある回答が含まれていた。原始ログと自動スコアは変更せず、AIによる用語集との事後照合を別ファイル `results/semantic_review_after.json` に残した。これは独立した人間による採点ではない。

|質問|学習後の出力・挙動|評価上の注意|
|---|---|---|
|LoRAの定義は？|用語集の定義を再現|形式・内容とも自動合格。定義との照合でも整合|
|質問と模範回答のペアによる追加学習を説明|用語集にないモデル名「bge3-small」を断定|自動合格だが、SFTの説明として不適切|
|Model Context Protocolの役割|「gemini_ai_context_tool_use」「openai_context_tool_use」を例示|自動合格だが、用語集に根拠のない具体例を追加|
|LoRAを名称なしで説明|全重みを1つの行列に丸める、2つのモデルで適用する等と回答|必須語はあるため自動合格したが、方法の説明に誤り|
|ハルシネーションを名称なしで説明|「LLMは学習していない」と付加|自動合格だが、誤った追加説明がある|
|overfitting時の未知入力への性能|正しい定義の後に、不適切な訓練データの説明を付加|キーワードの有無だけでは回答全体の整合性を確認できない|
|ACTN3 R577X多型とは？|MCPクライアントのパラメータとして説明し、needs_review=false|用語集にない内容を別領域の説明へ置き換えて断定|
|既定モデル名と切替変数|用語集にないモデル名・URLを提示|切替変数は含んでも、モデル名を正しく答えられていない|

「核心を満たし、誤った追加説明や未収録語への断定を含まない」という厳しい事後基準では、学習後は11/30件（36.7%：用語名10件＋レート制限の言い換え1件）を合格と判断した。自動採点合格16件中5件が不合格となる。これは**事後の補助評価**であり、学習前後で事前定義した自動指標53.3%を置き換えるものではない。

また、学習前のoverfittingの言い換え回答は、性能低下という核心には答えていたが、要求した「学習データ」等の語を含まず自動不合格だった。したがって、学習前0%から「学習前には知識が全くなかった」とは結論できない。

### 5. 検索との比較・考察

**追加学習が向く条件**：今回、同じ生成指示の下でJSONの形式遵守と、用語名を明示した質問への定義再現は改善した。安定した教師データがあり、出力形式や特定の回答パターンを適応させたい場合には候補になる。ただし、この実験では形式改善と定義の記憶を分離する対照条件は設けていない。

**追加学習だけでは不十分だった条件**：未収録語への確認要求は学習後も0/10件だった。教師データ116件はすべてneeds_review=falseであり、未知語の負例を追加していない。この偏りが断定を促した可能性があるが、負例を追加した対照実験を行っていないため、原因とは断定しない。loss低下やJSON形式の成功だけで、根拠範囲を判断する能力が身に付いたとはいえない。

**名称検索が向く条件**：用語名が明示され、正確な定義や出典を返す必要がある場合、今回の規模では直接参照する方式が有効だった。用語集の更新を再学習なしに反映でき、取得した定義を追跡できる。一方、名称なしの質問で5/5件の検索漏れが生じた。意味検索や用語抽出で改善できる可能性があり、この結果を検索方式全般の限界へ一般化すべきではない。

|判断基準|LoRA追加学習|今回の名称検索|
|---|---|---|
|定型形式・文面への適応|形式遵守と既知定義の再現が改善|JSONはコードで構築、文面は原文|
|言い換え|自動6/10だが、意味照合では誤りが多い|5/10。名称なしの5問は取得できない|
|未収録語|10/10で断定し、確認要求なし|10/10で確認要求。ただし検索漏れと区別できない|
|知識更新|教師データ変更後に再学習・再評価が必要|用語集の更新を参照できる|
|根拠提示|回答と元定義の対応を別途照合する必要|取得した項目と定義を示しやすい|
|今回のコスト|T4で約22.6分の学習|モデルの学習不要|

本課題の用語案内では、まず外部用語集の参照を基本にし、必要なら用語抽出・意味検索を追加する設計を選ぶ。学習を使う場合は、回答形式などの適応と知識参照を分け、未収録語の負例・名称なしの言い換え・誤った断定を評価する。検索と追加学習の併用は有望な候補だが、本実験では未検証である。

### 6. 制約・再現性

- 1モデル・1seed・各群10問の単回実験。質問の選定と厳しいキーワード条件に依存するため、性能差の統計的有意性や他条件での再現は主張しない。
- 検証用58件はeval_datasetとして渡したが、途中評価・最良モデル選択は設定していない。学習lossから過学習の有無は判断できない。
- 学習時には用語の定義を教師として与え、評価では同じ用語の別質問を使った。定義の再現と未知の知識獲得は区別する。
- **系列長監査の不備**：元の `lengths.json` のmax=2は不正な監査値。こちらで作成したコードが、`apply_chat_template` の辞書形式の戻り値にlenを適用し、トークン数ではなくキー数を数えたためである。これを根拠に512トークン超過なしとは主張できない。`scripts/lec02_experiment.py` では `return_dict=False` を指定して修正した。修正版のGPU実験は再実行しておらず、本稿の数値は元の実行結果のままである。
- `preparation.json` のtraining_executed=falseは準備時点の履歴であり、最終結果ではない。学習済みを示す最終記録は `results/result.json` のtraining_executed=true。原始ファイルは上書きしていない。
- mainの用語集と実験時の用語集はADK項目の記述が異なる。mainを変更せず、実験時の用語集を `data/glossary_snapshot.json` に保存した。SHA-256は `36e93d3120923db7097f060b70e7c5828e6ee333b8dfb7cbefd9443ffda9a3fe` で準備ログと一致する。
- AI支援でデータ・コード・文章を作成し、本人がColabで学習を実行した。今回の結果整理ではAIが全評価出力を用語集と照合し、採点・集計を再計算した。人間による独立した採点は実施していない。
