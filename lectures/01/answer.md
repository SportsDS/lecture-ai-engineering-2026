# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：一般的な3段階の難易度として説明したが、講座固有の定義は答えられなかった。
- 用語集の正しい意味と比べて気づいたこと：モデルは講座の用語集を参照していないため、もっともらしい一般論を返した。
- 表示できたトークン数（入力 / 出力）：21 / 629（温度0）
- 応答時間：3.23秒（温度0）

## 宿題

- 取り組んだレベル：基礎 / 実装 / 発展

### 基礎：同じ質問を3回ずつ比較

実行条件：`gemini-3.5-flash-lite`、同じ質問、温度を0 / 0.8 / 1.2に変更。

回答の違い：温度0では一般的な基礎・応用・発展の3分類を説明し、温度0.8ではAI活用や開発難易度など複数の解釈を提示した。温度1.2では簡潔な難易度分類になった。いずれも講座固有の正確な説明にはならなかった。

| 温度 | 応答時間 | 入力トークン | 出力トークン |
|---:|---:|---:|---:|
| 0 | 3.23秒 | 21 | 629 |
| 0.8 | 3.24秒 | 21 | 690 |
| 1.2 | 3.06秒 | 21 | 479 |

### 実装：会話履歴

`uv run python -m app.ask --interactive` で、最初の質問を受けたあとに回答内容を踏まえた追加質問をした。追加質問でも最初の回答を踏まえた説明が返り、会話履歴が引き継がれた。入力トークンは最初の17から追加質問では601に増えた。

### 発展：応答時間・トークン数

比較したモデル・質問：`gemini-3.5-flash-lite` で、宿題の3レベルとLoRAを質問。

結果（応答時間 / 入力トークン / 出力トークン）：3レベルは3.86秒 / 17 / 567、追加質問は3.66秒 / 601 / 556、LoRAは4.29秒 / 7 / 545。

無料枠のレート制限との関係：短時間に繰り返し実行すると、リクエスト数やトークン数の制限に達して HTTP 429 になる可能性がある。会話を続けるほど入力トークンも増えるため、応答時間や無料枠の消費量にも注意が必要である。

気づき・疑問：温度を変えると回答の長さや説明の切り口が変わったが、講座固有の知識がない問題は解決しなかった。会話履歴を長くすると入力トークンが増えるため、必要な履歴だけを残す工夫も必要だと感じた。
